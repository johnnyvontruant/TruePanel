# AEGIS Black Box calibration corpus

The `aegis-black-box-corpus-v1` fixture set turns AEGIS correlation calibration
into a replayable data contract. It contains 193 privacy-sanitized Black Box
frames across six deterministic scenarios: fan-bearing degradation, ambient
warming, workload warming, a transient RPM fault, telemetry dropout, and fan
sensor noise.

Each JSONL recording is immutable and content-addressed by `manifest.json`.
The loader rejects changed bytes, duplicate IDs, path traversal, oversized
corpora, non-monotonic replay, unsupported schemas, missing challenge classes,
and fixtures that would only become sanitized while loading. This last check
matters: `privacy: sanitized` is a claim that CI verifies against the bytes at
rest, not a label it trusts.

The preserved report is
[`evidence/aegis-black-box-corpus-v1.json`](evidence/aegis-black-box-corpus-v1.json).
It records both the manifest digest and a digest over the computed report.

## Authority and limitations

All recordings are synthetic fixtures generated by
`development/tools/generate_aegis_corpus.py`. Replay is deterministic, has no
wall-clock sleeps, and has no hardware, service, storage, network, or recovery
authority. These measurements prove behavior against declared cases; they are
not a production accuracy estimate. Mission Control therefore says **LAB
CALIBRATED · NOT LIVE VALIDATED** instead of implying field trust.

The strongest next evidence step is an opt-in, reviewed corpus of sanitized
normal workloads and real incidents, versioned separately so synthetic and
field evidence cannot be confused.
